LOG 002 / BUILDS

Two systems, shipped and running.

Most teams shipping AI chatbots have no visibility into what the model is actually saying to users once it's live. SentinelAI watches for that — in real time.

A three-signal detection engine catches failure modes a single metric would miss: TF-IDF cosine similarity for semantic drift, Isolation Forest for anomaly detection, and a CUSUM statistical control algorithm for gradual quality decay. A multi-tenant FastAPI backend learns each tenant's "normal" from live usage rather than hardcoding it, with a 50-sample warmup phase to cut false positives during cold starts. Alerts reach Slack within 60 seconds of detection.

Python · FastAPI · scikit-learn · Streamlit · Supabase (PostgreSQL) · Render · Slack Webhooks
→ live dashboard

field notes

  • chose TF-IDF over sentence-transformers — 512MB RAM constraint on Render
  • added 50-sample warmup after early false-positive spikes on cold start
  • own full lifecycle: architecture → ML pipeline → backend → deploy → UI

Contracts are dense on purpose. This tool fine-tunes DistilBERT on the CUAD dataset (Contract Understanding Atticus Dataset) to flag and classify clauses across 34 legal risk categories — then hands each flagged clause to Llama 3.3 70B via Groq to explain, in plain English, what it actually commits you to.

Upload a contract, get clause-level risk flags with explanations in one pass — a multi-step NLP pipeline collapsed into a single usable tool.

Python · Hugging Face Transformers (DistilBERT) · Groq API (Llama 3.3 70B) · Streamlit
→ live dashboard

field notes

  • fine-tuned DistilBERT solo — reached ~75% accuracy across 34 categories
  • handled full pipeline alone: preprocessing → fine-tuning → prompt design → frontend
  • LLM layer added specifically so non-lawyers can read the output
